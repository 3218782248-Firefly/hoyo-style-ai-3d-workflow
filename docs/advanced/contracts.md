# 数据约定

建议目录：`references/`、`assets/original/`、`assets/working/`、`textures/source/`、`textures/export/`、`shots/`、`cache/`、`renders/`、`delivery/`。原输入和采用工程保留，缓存可再生必须有真实运行过的恢复入口。

## 控制图

每张控制图记名称、用途、UV 集、颜色空间、R/G/B/A 语义和接入节点。只记录正在使用的实现，不将一个库的通道规则套到另一个库。改图后回到实际工程检查，不只验图片尺寸。

## 节点

从最终 Surface 开始追踪活动连接；节点组内外都需核对。存在但没有接入、已经接入但混合权重为零、接入且对画面实际生效，是不同状态。自动盘点只记录结构，不自动推断全部动态分支与美术效果。

## 外链

初始化脚本记录外部图片和链接库；实际项目可能还有模拟缓存、几何节点外部数据、字体、影片与自定义脚本。必须检查盘点中的 `manual_dependency_review`。工具没有承诺自动发现任意插件的全部依赖。

## 与前一个工具项目配合

CG Workbench 负责输入代次、帧验证、恢复和编码；本仓库负责角色制作流程与 Blender 工程接口。固定依赖提交，不复制一套同功能执行器。人工美术审查和是否采用仍写在项目记录中。
