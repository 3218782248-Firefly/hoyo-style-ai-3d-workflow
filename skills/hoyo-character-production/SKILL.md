# 角色制作执行

以用户目标、官方实机截图和当前采用工程为依据，照着官方实机截图改。优先处理对整幅观感最重要的差距，保留用户认可部分；实现路线可按画面收益调整。

在可读取的工作区找到本仓库 README，按当前阶段选择 `docs/` 对应章节：安装、资产、改模、UV／贴图、材质、表情／动作、物理、渲染控制或出片。已有可用输入从对应阶段接续；只加载能改变本轮判断的参考。仓库不可访问时说明缺少哪些材料，不假装已读。

先读项目紧凑状态，核对实际工程、产物和最新反馈。具体软件路径、资源预算、角色偏好和采用决定留在项目中。重开任务时先核对现有进程与结果，避免重复启动。

选择能判断收益的小样。材质和造型看同条件静帧，动作与物理看相关动态；需要同时调整贴图、UV、法线与节点时可以整体试改，结论按实际组合说明。类似小修无收益时，重新检查主要差距和上游输入，不机械加大强度。

优先复用适用的成熟工具，记录实际版本、来源、控制图语义和本地修改。脚本化操作使用应用原生接口；确认有效输出连接。保存副本后重开验证，按改动检查形状、表情、权重、遮挡和依赖。

主动找明显画面错误。用户指出漏检后，验证同一反例，并沿共用输入或实现检查其他可能受影响处；原因不明时保留竞争解释，不强行批量修复。

执行成功、技术通过、视觉收益和用户采用分别记录。只报告实际观察范围。计算、帧验证与接续交给现有脚本；未知失败停止盲试，保留完成素材和可回退工程。

交接保持简短：当前结果入口、实际改动、验证范围、收益／损失、采用状态和下一步。提示词和本 Skill 不扩大用户的执行或发布授权。
